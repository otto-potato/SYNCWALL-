# SYNCWALL 使用教程

## 一、准备服务端电脑

推荐使用最新版 Chrome 或 Edge。服务端电脑需要安装 Node.js `22.13.0` 或更高版本。

打开终端并检查：

```bash
node -v
npm -v
```

如果没有显示版本号，请先从 Node.js 官方网站安装 Node.js。

## 二、安装并启动

在终端进入本目录：

```bash
cd syncwall-server-clean
npm install
npm run dev
```

第一次执行 `npm install` 会下载依赖，耗时取决于网络。安装完成后，后续启动只需要：

```bash
npm run dev
```

终端会显示本机和局域网访问地址。不要关闭这个终端窗口。

## 三、连接控制端和被控端

假设服务端电脑的局域网 IP 是 `192.168.1.20`：

- 控制端打开：`http://192.168.1.20:3000/admin666`
- 所有被控端打开：`http://192.168.1.20:3000/`

除 `/admin666` 外，其他网页路径默认都是被控端。

每台被控端按首次连接顺序获得固定小写设备码，例如 `aa`、`ab`、`ac`。调整设备左右位置时只会改变显示序号，设备码不会改变。

每台被控端都应先点击“启用声音”或“准备播放”，否则浏览器可能阻止带声音的自动播放。

## 四、时间校准

1. 控制端点击“开始校准”，所有被控端进入校准页面。
2. 点击“显示时间码”，观察各设备的实时浏览器时间。
3. 点击“静止时间”。系统使用 2000ms 校准安全窗口，让所有设备在统一目标时刻冻结显示并回传时间。
4. 点击“自动校准”，系统修正每台设备的独立浏览器时钟偏差。
5. 如仍有细微差异，点击“手动校准”，在对应被控端以 `1ms` 或 `10ms` 为单位微调。
6. 完成后点击“返回播放”。

时间校准修改的是每台设备在本系统内使用的独立时间，不会修改电脑操作系统时间，也不会覆盖设备播放延迟补偿。播放延迟需通过指定设备叮声单独校准。

## 五、播放视频或音频

1. 控制端点击“上传音频/视频”。
2. 等待控制端上传完成。
3. 等待每台被控端的分发进度达到 `100%`。
4. 如果某台设备显示“需点准备”，在那台被控端点击“准备播放”。
5. 所有设备就绪后点击“同步播放”。

播放命令会指定统一的绝对播放时刻，目标时间为控制端下发命令时的服务端时间加 `3000ms`。网络延迟用于时间校准；设备播放延迟补偿不会改变统一目标时刻，而是在被控端本地修正媒体实际启动时机。

“暂停全部设备”会保留当前进度；“全部停止”会立即停止并把进度归零。

开启“循环”后，每一轮结束前控制端都会重新向所有设备下发下一轮的绝对播放时间。

## 六、多屏画面

设备按照进入后的当前位置从左到右排列。控制端可以使用设备卡片上的左右按钮调整顺序。

播放视频时，系统把完整视频横向铺到所有屏幕组成的总宽度，再让每台设备显示自己对应的片段。底部进度条同样跨屏显示。

增加或减少设备后，画面会按照当前在线设备数量动态重新计算，不限定为五块屏幕。

## 七、其他功能

- 校准音：先在控制端选中目标设备，再点击“播放校准叮声”。校准音只发送给该设备。
- 手动延迟：只影响校准叮声，可输入正数或负数；修改后会立即重新测量网络延迟。
- 音量：选中设备后单独调整该设备的媒体音量。
- 图片：选中设备后可只向该设备发送图片，也可以单独清除。
- 时间码：停止或暂停状态下可逐帧前进、后退、输入时间码并选择常用帧率。

## 八、关闭服务

在运行服务的终端窗口按：

```text
Ctrl + C
```

正常关闭不会删除本地数据库或已上传媒体。
